Browspark is a local [Model Context Protocol](https://modelcontextprotocol.io) server with 43 `browser_*` and `devtools_*` tools. Any MCP client, such as Claude Code, Codex, OpenCode, Cursor, Kilo or Antigravity, can use shared tabs in Chrome and Brave or separate Chrome, Brave, Firefox and Zen developer sessions. Multiple browsers can run together through one companion, which listens on `127.0.0.1` only.

  </Card>
  <Card title="Read and extract" icon="file-lines" href="/guides/read-and-extract">
    Turn a page or a URL into clean markdown, pull tables, links and structured records, print to PDF, and call tools that pages expose through WebMCP.

  <Card title="Debug like DevTools" icon="bug" href="/guides/debug-a-web-app">

  <Card title="Profile and audit" icon="gauge-high" href="/guides/performance-and-memory">
    Performance traces with Web Vitals, CPU profiles, heap snapshots and leak checks, code coverage, and Lighthouse reports in Chrome's own file formats.

## Two ways to reach a browser

| Mode | What it is | When it is used |
|---|---|---|
| **Extension mode** | Shared tabs in your own Chrome, Brave or another supported Chromium browser. Each profile has its own dashboard and sharing controls. | Everyday work with your existing sessions and cookies. Work in background is on by default. |
| **Developer mode** | Separate Chrome, Brave, Firefox or Zen sessions with persistent profiles and named contexts. | Explicitly requested browser sessions, cross-browser checks, or capabilities Chromium blocks for extensions. |

Firefox and Zen keep the same tool names with [documented exceptions](/reference/firefox), including raw CDP, Lighthouse and Chrome profiling. Connected dashboards control whether developer browsers may launch. See [Modes](/concepts/modes) and [Using multiple browsers](/reference/multiple-browsers).
